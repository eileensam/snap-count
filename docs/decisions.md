# Decisions

Judgment calls made along the way, and why, kept here so we don't relitigate them.

- **No team-count cap in the pool rules.** Only the $250 budget caps a roster. Confirmed 2026-08-30; v1's docs had assumed a fixed 4-team roster, which was wrong for this season (and possibly always was, not verified against pre-2026 seasons).
- **Snap-Count does not track money.** Entry fees and prize payouts stay the commissioner's manual process. The site only ever shows wins/points/rank.
- **v1 archived via git tag only (`v1-2025-season`), not a browsable path.** Simpler than maintaining a live archive page; git history is sufficient.
- **Pick-helper is explicitly not a recommendation engine.** Shows data (price, division, budget math) and lets the player draw conclusions, rather than ranking or suggesting a lineup. This avoids steering people's picks in a competitive pool.
- **No build step/framework by default for v2**, same as v1; only add tooling with a concrete reason for the specific piece of work being built.
- **Repo stays public on GitHub Pages, stays static.** Considered GitHub Pro (private repo + Pages) and Railway (already-paid hosting) to go private; decided against for now, no concrete need. Revisit only if the pick-helper needs to become a shared submission mechanism (tracking who's actually submitted picks across players, not just personal exploration): that would need persisted shared state localStorage can't provide.
- **Phase 1 replaces `index.html`** as the homepage immediately, rather than living at a separate path alongside the old leaderboard. No live season data exists right now, so the old leaderboard has nothing current to show.
- **Vintage sports magazine aesthetic over the initial pixel-art and catalog-ephemera directions.** See [design/system.md](design/system.md) for the settled system; the rejected directions and why are worth knowing so they don't get re-proposed: 8-bit pixel font read as a dated, played-out kind of retro; a mail-order catalog register (product codes, stamps, dotted-leader price lists) overindexed on one narrow slice of the inspiration and read as fussier than intended.
- **Type pairing: Oswald for big/display text, Bodoni Moda for small/body text.** Originally the reverse (Bodoni display, Jost body), echoing Vogue's own historical pairing. Jost was rejected outright, then Big Shoulders Text and Anton were both tried and rejected for display (too thick/wrong feel) before landing on Oswald, a revival of Alternate Gothic, the lettering actually seen on vintage American sports posters and programs. Once on Oswald, the hierarchy flipped too: big text reads better in the sports-poster sans, body text in the Vogue-adjacent Didone serif.
- **Day-one gameday launch (2026-09-08) splits the site into three pages** rather than waiting for the full Phase 2 rebuild or hardcoding placeholder data: `index.html` (games this week plus a leaderboard shell), `team-picker.html` (the Phase 1 pick-helper, renamed), `rules.html` (plain rules page). Reasoning: not everyone will have picks in by kickoff, but a games/point-stakes view needs no pick data at all, so it can launch honestly rather than shipping either a rushed full leaderboard/graph/cards UI (still being designed) or a throwaway placeholder page. `team-picker.html` stays reachable for stragglers and gets decommissioned once picks settle. **Superseded 2026-09-09**, see the nav/tabs merge decision below for the current cross-page nav order.
- **The games list is fetched live from ESPN's public scoreboard API, never hardcoded.** Typing in a week's matchups by hand is exactly the "weekly hand-maintenance" problem `roadmap.md` cites as a reason for the v2 rebuild in the first place. Postseason point-stake display (3/3/5/5) isn't wired up yet, only regular season's flat 1 point per win; not needed until the playoffs.
- **The rules page omits the family name.** It's a public, static page (see the repo-visibility decision above), so `rules.html` says "this pool" rather than naming the family. Internal docs (this file, `pool-rules.md`) still use the real name for the team's own reference. The page also only covers Scoring and Prizes, not Entry or Groups, a deliberate cut, not an oversight.
- **Cross-page nav and in-page tabs merged into one row (2026-09-09): Leaderboard · Games · Rules**, same style everywhere, current item bold, no separate tab-bar treatment. Originally nav (Home/Rules) sat above a visually distinct tab bar (Leaderboard/Games); user feedback was that two different-looking row-of-labels switchers stacked on top of each other read as one confusing nav. "Home" is retired as a concept, its job absorbed into Leaderboard/Games, which link to `index.html` (optionally `?tab=games`, read on load to open the right tab) from other pages and act as in-page tabs on `index.html` itself. This also supersedes the old "Rules first" nav-order rule above; Rules is now last.
- **Trajectory graph: hover/tap tooltip instead of always-visible end-of-line labels.** Labels stacked on top of each other whenever players were tied (common, not just early season), and were cramped once several Small Group players landed close together. Every point on every line (Full League included, not just Small Group) now has an invisible hit-target; tapping/hovering shows player and points in a small flip-side tooltip. Small Group lines still get a persistent colored dot at every week so they're visible without interaction; Full League lines stay faint, unlabeled background context unless tapped.
- **Leaderboard rank 1/2/3 use real gold/silver/bronze**, not the five-color content palette, same precedent as team badge colors (see [design/system.md](design/system.md)): it represents an actual placement, not a generic accent.
